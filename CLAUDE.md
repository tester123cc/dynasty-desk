# Dynasty Desk — notes for Claude Code

Single-file static web app (`index.html`) served by GitHub Pages at tester123cc.github.io/dynasty-desk. It is for two Sleeper superflex dynasty leagues. Leaguemates use the same link, so **always update `index.html` in place** (same filename), and never make a change that assumes every visitor is the user. Bump the footer version (`<p class="foot">Dynasty Desk vX.Y</p>`) with each release and add `?v=N` to the URL to bust the cache.

## Layout
- `index.html`: the whole app (CSS, JS, embedded snapshot data). The 2027 rookie board is a second single-file page embedded as the string `RB27_HTML` in a persistent iframe; parent and child talk by `postMessage` (`dd-live`, `dd-draft`, `rb27-ready`, `rb27-h`, `rb27-haul`/`dd-haul`).
- `scripts/fetch-data.mjs`: nightly values job. `scripts/crawl-trades.mjs`: market trades from KeepTradeCut's trade database. Workflow: `.github/workflows/data.yml`, daily 09:17 UTC plus manual dispatch. Outputs `data/values.json`, `data/history.json`, `data/market-trades.json`. First ran Nov 20, 2026.
- `data/history-weekly.json`: one-time weekly backfill (Aug 28 to Nov 20, 2026) from DynastyProcess's git history, made by `scripts/backfill-history.py`. Kept separate so the nightly job never conflicts with it.
- `scripts/rb27.py`: edit the embedded 2027 Board (`out` to a file, edit, `in` to re-embed; `check` confirms the round trip). It handles the JS string escaping, including `\uXXXX`. Rookie board sources otherwise live in `/home/claude/rb27` in cloud sessions only.
- `scripts/grade.mjs` (nightly, after fetch-data): records the site's predictions before games, grades them after, retrains, writes `data/predictions.json`, `data/grades.json`, `data/model.json`, `data/h2h.json`. `scripts/backfill-picks.py` (runs in the workflow only when `data/pick-hits.json` or `data/pick-seasons.json` is missing; delete a file to rebuild it) uses DynastyProcess git history via api.github.com, which the cloud sandbox cannot reach.
- `scripts/claude-board.py` (nightly): Claude's 2027 draft board, `data/claude-board.json`. Trains a logistic regression on every QB/RB/WR/TE drafted 2015 on (nflverse `draft_picks.csv`; outcomes from Sleeper season stats, same hit definition as pick hit rates) with three factors: good college seasons before the draft (ESPN college stats via `site.web.api.espn.com` search and `/apis/common/v3/sports/football/college-football/athletes/<id>/stats`, cached in `data/college-cache.json`; prospects refresh weekly), NFL pick (log), and landing offense (team points per game the season before, z-score, from nflverse `games.csv`). Checked by leaving one draft class out, against draft pick alone. Prospects are the 2027 Board's `RAW` rows; before the NFL draft the pick is Kiper's rank or a projection from the dynasty consensus, and landing is average; after the draft nflverse's real pick and team replace them automatically. ESPN and Sleeper are blocked from the cloud sandbox; test changes by dispatching the workflow on the branch.
- `tests/draft-harness.js`: fakes only the Sleeper draft endpoints behind `jget` so live draft sync can be tested without a live draft.

## Key internals
- Values: DynastyProcess CSV + FantasyCalc (per-league ppr/numQbs) + KeepTradeCut, blended by `S.weights`; `adj = value*mult*ageF*modeF`. `mv(p,L)` is market value without age discount (used for trade grading). KeepTradeCut's rankings page keeps players in `<script id="ktc-players">` JSON (changed in 2026; the old `playersArray` scan now finds only 3 featured players); `parseKTC` reads the new block first (same code in `scripts/fetch-data.mjs`). Browsers can't fetch KeepTradeCut (CORS, and the proxies return 401), so the app uses the nightly copy in `data/values.json` when it is under 48h old. Missing player ages are filled from Sleeper birth dates (`BDX`, `applyBD`), refreshed with injuries every 4h.
- Caching: `memo()` results and the odds/projection caches are keyed on `VER`. **Bump `VER` whenever async data lands** (values via `build()`, injuries/teams in `refreshInjuries`, market trades in `loadMkt`, history in `loadVHist`); forgetting this caused stale playoff odds and empty trade suggestions.
- Offers: `makeOffers`/`makeSells`, tuned by `learnTrades(L)` (league trades plus market trades). `makeRebuildOffers` (v7.15) sells veterans (26+) for young players (24.5 or under) and 1st/2nd-round picks, scored on the lineup 3 seasons out (`fct` aging; picks at 75%) and requiring the partner's lineup now not to drop; one offer per team, the same package at most twice. `posNeed` (v7.16) weights your side of `makeOffers`/`makeSells` by position need: your starters at each position vs the league median (QB counts the superflex slot), weak spots up to 1.4x, deep ones 0.9x; in superflex a trade may not leave you with fewer starting-caliber QBs. `rbOffers` turns it on when the league's Strategy is Rebuild, or when no strategy was chosen (`S.modeSet`) and the team grades as Rebuilding. Pending trades: `PENDING`, `pendCard`.
- Draft order: `projOrder(lg)` runs 1,000 season sims (drives My picks slots); falls back to `draftOrder` (today's order, used by Home and Roster). The "Projected final draft order" card runs its own 700-sim `projSim`. Pick ids: `pk_<lg>_<round>_<origRoster>[_yy]`.
- Live draft sync (v7.14): `drFind` looks for the 2027 rookie draft (season 2027, not auction, 8 rounds or fewer) in the league's drafts and in its 2027 renewal (`/user/<id>/leagues/nfl/2027` where `previous_league_id` matches). `drPoll`/`drTick` poll `/draft/<id>`, `/picks` and `/traded_picks`: every 8s while drafting, 60s paused, 30s within 3h of a scheduled start, else 5 min; slower when the tab is hidden; restarted after each Sleeper sync. `drPayload` goes to the board as `dd-draft`; the board matches names with `nkey` (drops Jr/Sr/II), makes `x_` stub players for picks not on the board, stores it in `S.sl`, and shows it on Draft day (`vSync`), Board (taken tags) and Mock ("Start from the live draft"). Once Sleeper has a draft order, `dd-live` sends that order and snake setting.
- Rookie rankings: `RK.pros` (Draft → Board, My picks) is generated from the 2027 Board's `RAW` rows and uses the same consensus formula. If you update the 2027 Board, regenerate `RK.pros` too.
- Trend arrows: `loadVHist` merges `data/history-weekly.json` with the nightly `data/history.json` (nightly wins on shared dates). `vtrend` compares a player's latest expert value with ~4 weeks earlier (1 week if that is all there is); `mtrend(p,lg)` (v7.16) does the same for market value in the league's format: nightly history rows now carry `m:{A,B}` (FantasyCalc, top 400) and, until that covers a week, it falls back to FantasyCalc's own 30-day trend (`p.tr`, now scaled like the values). `tarr(id)` shows whichever moved more and puts both in the tooltip; ▲/▼ at 8%+ and 150+ points, double at 20%+ and 400+. Arrows sit next to every `ibx()` injury tag and on the value board; Roster's Rising and falling card still uses expert values.
- Week tab (v7.16, Team → Week, the default Team tab): `loadProj` gets this week's projections from `api.sleeper.app/projections/nfl/<season>/<week>` (array or object shape, both handled by `projNorm`), else `data/proj.json` from the nightly job; cached in `dd2proj` for 1h. `wkProj` scores with the league's `scoring_settings` (`LGI[lg].sc`, saved at sync), else Sleeper's half/full PPR totals; Out/IR/suspended/bye count 0, doubtful 30%. `bestWk` fills fixed slots, then FLEX, then SF. Sync now keeps each roster's Sleeper `st` (starters), `res` (IR) and `tx` (taxi), and the current week's matchups in `MU` (`dd2mu`). `wkCtx` compares your set lineup with the best one and gives a win chance (normal, sd 40% of projection + 1.5 per player); `weekCard` puts it on Home.
- Share links (v7.16): `#trade=<lg>~<from>~<to>~<ids>~<ids>` (ids joined by `.`). `readShare` at boot and on `hashchange`; `applyShare` loads it into the Builder from the opener's side if they are one of the two teams (re-run after sync until every piece is found); `sharedCard` grades it for both teams. Builder has a Share link button (`navigator.share`, else copy).
- Grading (v7.16): for every team in both leagues, `grade.mjs` predicts each week (win chance from set starters, start/sit calls where the best lineup beats the set one by 0.5+, raw projected points for every rostered player) and re-saves it each run until that week's points start, then freezes it. Weeks before grading began are rebuilt from Sleeper's archived projections with the untrained model and marked `bt` (backtest). After games it grades: Brier score and calibration bins for win chances, start/sit hit rate and net points, projected vs actual by position, and trade grades (expert value on the trade date from the history files vs today; "held up" once 28+ days old). Training: position bias = (actual+300)/(projected+300), capped 0.8 to 1.2; `sdK` by log-likelihood grid search, shrunk toward 0.4 by n/(n+40). The app reads `data/model.json` (`mdl()`) in `wkProj` and `sdOf`. Alerts (in `grades.json`, plus the app's own "grading stopped for 3+ days"): win chances worse than a coin flip three live weeks running, Brier > .245 over 36+ games, 70%+ favorites winning < 55%, start/sit < 45% over three live weeks, a position's raw bias outside 0.8 to 1.2, trade grades holding < 40% over 6+ trades. "watch" items are informational. The Home banner shows only when viewing as the site owner's own team (`me.u`, the Sleeper account the app syncs); everyone sees alerts on the Grades tab and a red dot on its nav button.
- Draft → Claude (`pClaude`, `loadCB`): the board above, tap a player for college seasons; "What history says" shows plain hit rates by pick, good college seasons and landing offense. Draft sub-tabs are Order, My picks, Board, 2027, Claude.
- Grades tab (`pGrades`, `pGradeLog`), League → H2H (`pH2H`, from `data/h2h.json`), My picks → "How often picks like yours hit" (`hitCard`, `hitAt` pools the slot and its neighbors) and "When to sell picks" (`sellCard`, `seasonCurve`: upcoming-draft 1st value by month, each season scaled to its own median).
- Market tab: `pMarket`, `mktItem`, `mktRows`; KeepTradeCut ppr codes 1=0, 2=.5, 3=1, 4=tiered; tep 0-3.

## Sleeper API facts (checked Nov 20, 2026)
- Public, read-only, no key. Transactions only include `complete` and `failed` moves; **trade offers still waiting for an answer are never returned**, so pending-trade grading cannot work. The Builder is the path.
- Draft picks carry `pick_no`, `round`, `draft_slot`, `roster_id` (who picked) and `metadata` (`first_name`, `last_name`, `position`, `team`). Snake round 2 pick 13 is labeled 2.01.
- `/players/nfl` is about 5 MB; the app fetches it at most every 4h for injuries, teams and birth dates.

## UI conventions (v7.16)
- Keep screens short on a phone: explanations go in `info(html,label)` (a small "How this works" toggle), filters in dropdowns (`.fsel`) or collapsed `details`, long lists paged (Market shows 20, +40 per "Show more"). Roster and Free agents rows open on tap (`UI.rx`) to show Watch (plus Block and Shop on Roster). Free agents (15, +25) and League Trades (8, +20) are paged; Tank or compete merges identical rows into ranges. Inside an offer card, the partner's own picks drop the team name (`pnIn`).
- Before and after a layout change, measure each screen at 375x812: height in screens, button count, and the share of explanatory text.

## Working rules
- Verify in a browser against a local server (`python3 -m http.server`), with live Sleeper data: check both leagues, every tab, and all six 2027 Board tabs, plus phone width. Scan rendered text for `${`, `NaN`, `undefined`, `[object` and watch the console for errors. Playwright works too where it is installed.
- Cloud sandbox network blocks Sleeper, FantasyCalc, KeepTradeCut. Treat live-data paths as unverified until tested on the user's computer or in GitHub Actions. Say so plainly.
- On the user's Mac: no Node, no Homebrew, no `gh` by default, and the python.org Python has no CA certificates (use `curl` for downloads; never disable verification). The GitHub app connector has failed with "Authorization header is badly formatted" (the plugin needs `GITHUB_PERSONAL_ACCESS_TOKEN`); the working path was the official GitHub CLI downloaded into the session folder (checksum and signature checked) and `gh auth login --web`, used per command via `git -c "credential.helper=!<gh> auth git-credential"`. Never handle or paste the user's tokens.
- GitHub: `gh api` REST only in cloud sessions (GraphQL is blocked). Push with `git -c push.negotiate=true push`. The data job commits to the branch it runs on, so pull/rebase before pushing. Commit trailers: `Co-Authored-By:` naming the Claude model that did the work, plus the session URL when there is one.
- When two open PRs touch CLAUDE.md, merge one, then merge `main` into the other and resolve by keeping both sides; check the result against `main` before merging.
- KeepTradeCut has no public API. We read its trade-database page's own POST (`/dynasty/trade-database/trades`) and its rankings page. Call each at most daily and do not hammer it.
